# 审查标记（review marks）

标记体系是**本仓自拟**的审查工作流，不是行业标准术语。

人工审查代码和设计文档时，把结论写在**被审对象旁边**；脚本在提交前汇总，
不靠人记、也不要求审查期间在代码和文档之间来回切。

标记是 `.md` / `.c` / `.h` 中以 `//` 开头的普通文本（行首 `#` 可能被当标题 /
预处理，故 `.md` 也要求 `//`）；C 块注释 `/* */` 也接受。描述可用行尾 `\`
续到下一行。

## 标签

| 轴 | 标签 | 含义 |
|---|---|---|
| 类型 | `#优化#` | 可改进，非缺陷 |
| 类型 | `#重构#` | 结构性改动 |
| 类型 | `#缺陷#` | 真 bug；按 R11 进台账 |
| 动作 | `#决策#` | 需要用户拍板 |
| 动作 | `#讨论#` | 需要讨论 |
| 状态 | `#未验#` | 代码已改，但没有 UT / 上板证据 |
| 状态 | `#标识保留#` | 已登记，暂不处理；标记保留、允许上传 |

- 同一行可放多个标签，空格分隔。
- **第一个标签决定报告分组**；后续标签只展示。
- `#标识保留#` **任意位置**都表示「允许上传 / `--strict` 放行」；只有放第一位才进
  「保留」组。
- 顺序示例：
  ```text
  #讨论# #优化# #标识保留#   → 需要拍板 / 讨论组；strict 放行
  #标识保留# #讨论# #优化#   → 保留组；strict 放行
  #优化# #讨论#              → 待做组（第一标签是类型）
  ```
- 不再增加 `#已优化#` / `#已验证#` / `#搁置#` / `#待后续#` 等近义词（C9）。
  完成就删整行；永久不修进台账。

## 写法

Markdown 也要 `//`：

```markdown
### 3.2 分配器 / BST / Super Block（allocator + bst）

// #讨论# #优化# #标识保留# allocator: 低 free 时成对分配失败是否应该回滚
// #缺陷# RISK-FTL-07 allocator: 低 free 时成对分配失败没有回滚
// #优化# #讨论# 第一段描述\
// 第二段描述
```

C：

```c
// #讨论# #优化# #标识保留# 低 free 时成对分配失败是否应该回滚
foo(); // #优化# 这里每次都重算，能否复用上面的结果

/* #优化# #未验# 这条路径还没上板 */
/*
 * #重构# 三套坐标收敛到单一漏斗
 */
```

- `//`、`/*`、`*/`、块注释行首的 `*` 会被脚本剥掉；`//#优化#` 和 `// #优化#` 都接受。
- 标记不能写在注释句子的中间；`// 先这样，#优化# ...` 不会被识别。
- Markdown 围栏代码块里的标记被忽略。
- **续行**：行尾 `\` 是最后一个非空白字符时，下一行继续拼进描述；直到某行不以 `\`
  结尾。
  - `.md` 和 C 的续行都必须仍以 `//` 开头；
  - C 续行必须是注释行，且紧邻上一行；
  - 报告里用空格拼成一行，源文件可以多行；
  - 悬空 `\`（后面没有下一行）报错。

## 生命周期

```text
#优化# / #重构# / #缺陷#          未做
#优化# #未验#                     已改，未验证
#优化# #标识保留#                 暂不处理，标记保留、允许上传
（删掉整行）                       已改 + 已验证
#决策# / #讨论#                   解决后删该标签；若还有实现工作，保留类型标签
```

- `#标识保留#` 不是完成态：问题还在，只是现在不改；标记不删。
- `#标识保留#` 任意位置都允许上传 / 放过 `--strict`；报告分组仍看第一个标签。
- 上面的生命周期是**状态组合示例**；要进「待验证」/「保留」组，把 `#未验#` /
  `#标识保留#` 放第一位。
- 处理完就删整行；文档不承载变更史（H37）。

## 台账规则

- 文档里的 `#缺陷#` 必须带 `RISK-*` / `ISS-*`，且编号必须在
  `docs/design/known_open_items.md` 或 `known_closed_items.md` 里存在。
- 代码 / 测试里的 `#缺陷#` **不带** `RISK-*`；台账的「证据定位」写
  `文件#符号`，链接在台账侧（R4 / R11）。
- 代码 / 测试注释里出现 `RISK-*` / `ISS-*` 只告警，不阻断。

## 扫描范围

```text
docs/design/*_design.md
src/**/*.c  src/**/*.h
include/**/*.c  include/**/*.h
tests/**/*.c  tests/**/*.h
```

不扫 `third_party/`、`Drivers/`、CMSIS/HAL。

## 命令

```sh
make review-marks          # 分组报告：保留 / 需要拍板 / 待验证 / 待做
make review-marks-check    # 只校验格式、未知标签、台账引用
make review-marks-strict   # 发布门禁：非保留标记即失败
make review-marks-test     # 检查器自检（C7 / P13）
```

`make check` 挂 `review-marks-check` 与 `review-marks-test`，不挂 `make all`。

## 报告分组

按**第一个标签**分组：

1. `#标识保留#` → 保留
2. `#决策#` / `#讨论#` → 需要拍板 / 讨论
3. `#未验#` → 待验证
4. 其他类型标签 → 待做

⚠ `#标识保留#` 不在第一位时，分组按第一位；`--strict` 仍放过，汇总的 retained
按「含 `#标识保留#`」计数。例：`#讨论# #标识保留#` 进「需要拍板 / 讨论」，但不阻断上传。

## 常见错误

- Markdown 标记不带 `//` → 失败。
- `\` 续行的下一行不带 `//` → 失败。
- C 续行没有紧邻上一行注释 → 失败。
- 悬空 `\`（没有下一行）→ 失败。
- `#优化`（缺闭合 `#`）→ 未知标签。
- `#优化#` 后没有描述 → 失败。
- 文档里 `#缺陷#` 没有台账编号 → 失败。
- 台账编号拼错或不存在 → 失败。
