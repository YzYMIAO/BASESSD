# 代码 / 文档审查

规则来源分三层，**按需加载**：

1. `.claude/rules/c-coding.md` —— H1~H50 / S1~S6 一句话规则（代码路径自动加载）。
2. `docs/guides/coding_rules.md` —— H 规则的 why / 反例 / 落点。
3. `docs/guides/coding_rules_generic.md` —— 通用 15 章 + 不采纳理由（**仅深审**读）。

⚠ 本 skill **刻意不复制**规范条目（H6）；只给审查流程与本仓特有检查点。

## 0. 选择模式

| 模式 | 何时用 | 读什么 |
|---|---|---|
| **快审（默认）** | ≤3 文件、非介质/建链/位图/地址 | `CLAUDE.md` + `.claude/rules/c-coding.md` |
| **深审** | 跨模块 / 介质格式 / 建链 / 位图 / 地址 / 大重构 | 上面 + `docs/guides/coding_rules*.md` |

快审也要过第 2 / 5 遍（资源与坐标）—— 这两类最容易出静默缺陷。

## 1. 审查顺序（六遍）

按「先结构后细节」走，**不要一上来就看表达式**。

### 第 1 遍 · 结构与模块（H10 / H11 / H12 / H13）

- [ ] 是否按 H49 顺序：命名 → 布局 → 调用链 → 封装 / 断言？
- [ ] 一个函数只做一件事？嵌套 ≤4 层？（**不设 50 行上限**）
- [ ] 头文件只放声明、自包含、有守卫、无循环依赖？（H12）
- [ ] include 是否**纯文件名**？（H41；`grep -rnE '^\s*#\s*include\s*"[^"]*/' src include tests` 应为 0）
- [ ] `static inline` 只放纯函数？（H42）
- [ ] accessor 过「三问」？全否应直接访问字段。（H13）
- [ ] **模块间有没有直接摸对方内部数据**？改 A 被迫改 B 的内部 = 耦合过重。（H13）
- [ ] 全局可变状态是否**单点修改**？（H10）
- [ ] 同一不变量是否被**多个模块手工维护**？（C3 / §3.1）

### 第 2 遍 · 资源与错误路径（H1 / H14 / H30 / C5）

- [ ] 申请 / 释放**配对**？（三池 / op release / `buf_own`；漏配对 ⇒ 池泄漏 → `FTL_AGAIN`，不报错）
- [ ] 库函数 / HAL 返回值处理了吗？允许 `(void)`，不允许静默忽略。（H30）
- [ ] 参数校验**只在模块入口做一次**？（H2）
- [ ] 该用 `ASSERT` 的地方用了吗？**有副作用的调用进 `ASSERT` 了吗**？（H14）
- [ ] 后果是**静默介质破坏**的错误，release 下有没有运行期拒绝？（C5 / 判据 9）

### 第 3 遍 · 类型与运算（H3 / H4 / H9 / H22 / H23 / H43 / H44）

- [ ] **隐式窄化转换**显式化了吗？（H22）
- [ ] 每个**显式强转**是否必要？（H43）
- [ ] 强转是否在**为过宽的 API 返回值**买单？（H44）
- [ ] 移位量 < 位宽？位运算只用于**无符号**？（H23）
- [ ] 溢出检查是「**先判后算**」？（H3）
- [ ] 魔鬼数字？（H4，必须注明来源与推导）
- [ ] 固定宽度整数用 `BYTE/WORD/DWORD/QWORD`（H9）；不写 `uint8_t`。

### 第 4 遍 · 嵌入式运行时（H16~H21）—— **最容易漏的一遍**

- [ ] `volatile` 只用于三处？顺序敏感处配 `__DMB()`？（H16）
- [ ] DMA 缓冲区做了缓存维护？32 字节对齐？（H17）
- [ ] 临界区用**可嵌套 PRIMASK**？（H18）
- [ ] 递归深度由**数据结构**保证？（H19）
- [ ] 长操作覆盖喂狗点？喂狗点是否被慢路径饿死？（H20）
- [ ] ISR 够短？有无阻塞 / 不可重入 / `LOG*`？（H21）

### 第 5 遍 · 复用与坐标（R9 / C2 / C9）

- [ ] 新增的位操作 / 地址转换 / 结构体构造 / 相似分支，**有没有手工等价物**？（C2）
- [ ] 出现**第二套坐标**了吗？（C9）
- [ ] 位图是不是 **flat 绝对编号**？plane 1 的 CW0 是 `bit 4`；`1U << cw` 是 plane 盲。
- [ ] 位判断是否走公共宏？分清「任一位置位」与「全部位置位」。（H15）

### 第 6 遍 · 注释与可读性（H5 / H6 / H26 / H27 / S1~S4）

- [ ] 注释与代码一致吗？（H6）
- [ ] 变量都初始化了吗？（H26）
- [ ] 跨边界结构体字节序写明了吗？（H27）
- [ ] 注释解释 why？在代码上方或右方？中文？（S2/S3/S4）
- [ ] 有没有对齐周围代码？（S1）
- [ ] 废弃代码、注释掉的代码清干净了吗？（H5）

## 3. 审查标记

设计文档行首或 C 注释体第一段内容写标记；脚本在提交前汇总，不靠人记。

```markdown
#优化# #讨论# allocator: 低 free 时成对分配失败是否应该回滚
#缺陷# RISK-FTL-07 allocator: 低 free 时成对分配失败没有回滚
```

```c
// #优化# #标识保留# 当前 API 冻结，等下一版再收敛
foo(); // #重构# 这里可以收敛到单一漏斗
```

| 轴 | 标签 |
|---|---|
| 类型 | `#优化#` / `#重构#` / `#缺陷#` |
| 动作 | `#决策#` / `#讨论#` |
| 状态 | `#未验#` / `#标识保留#` |

- 做完删整行；`#未验#` = 已改未验证；`#标识保留#` = 已知暂不处理，允许上传。
- 文档里的 `#缺陷#` 必须带 `RISK-*` / `ISS-*`；代码 / 测试里不带。
- 语法、生命周期、扫描范围见 [references/review-marks.md](references/review-marks.md)。

```sh
make review-marks          # 分组报告
make review-marks-check    # 只查格式与台账引用
make review-marks-strict   # 发布门禁：非保留标记即失败
make review-marks-test     # 检查器自检
```

## 产物格式

- 按**严重度排序**，每条一行：`文件:行号 — 问题 — 规则（R/C/H/P/S） — 建议`。
- 必须能说出**失败场景**（什么输入导致什么后果）；说不出 = 风格偏好，归 S，不当缺陷报。
- 报缺陷前按 **C7** 自问：**这条判断能失败吗**？
- **发现即登记（R11）**：缺陷 / 判定结论同步写进 `docs/design/known_open_items.md`；
  关闭时迁 `known_closed_items.md`。只在回复里列出 = 未完成。
- **不主动改代码**（R7 讨论期）；**不主动 commit / push**（R3）。
## 常见失败

- 只报风格偏好，没有失败场景。
- 恒真判据 / 只验一条。
- 把 §四 的有意设计报成缺陷。
- findings 不登记。
