# 架构与分层决策

本 skill 只做**决策流程**。分层图、层间契约、接口清单在 `docs/`，不在这里复制（H6）。

## 0. 先读

- `docs/architecture.md`（当前分层）
- `docs/design/fc_nand_design.md` §26（HIL / FTL / FCC / DRAM + 队列·门铃·完成；
  §26.3 是「新接口比硬件寄存器表」的判据）
- `docs/design/storage_controller_design.md`（知识参照，不是本仓现状）

## 1. 决策步骤

1. **定层**：HIL / FTL / FCC / DRAM；数据面 / 控制面 / 可靠性面。
   答不出就停下补理解。
2. **找出处**：§26 / SPDK FTL / `docs/reference/`。说不出出处标「本仓自拟」。
3. **新接口**：比硬件 FCC 寄存器表；无对应项就上移或剔除。
4. **场景轴**：DRAM 型 vs DRAM-less，说清对齐哪支。
5. **过取舍清单**：`storage_controller_design.md` §十一。
6. **偏离留痕**：代码注释写「偏离 Hxx，因为…」（P5）。

## 2. 稳定约束

- 同一语义只允许一套坐标（C9）；跨层转换只允许在单一漏斗发生。
- SoC 相关代码不进入 Controller / FTL / NAND **算法**模块；核心模块不直接 MMIO/HAL。
- 内存预算以链接脚本为准；提高 CH/CE/LUN 维度前先重新规划（分区表快照可能过时）。
- 「造请求者拥有 buffer 池」这类层间下界以头注释/设计文档为准，不在本 skill 复制。

## 产物格式

```text
定到哪一层 / 引的哪条出处 / 本仓现状差在哪 / 代价 / 验证状态
```

落不到文件或文档章节 = 还只是印象。

## 常见失败

- 归不到「哪条主线的哪一层」就动手。
- 拿 Linux / 通用 OS 当判据。
- 新接口没有寄存器表对应项。
- 不说 DRAM 型 vs DRAM-less。

- 改代码后按 R2 过三关；碰**建链 / 位图 / 地址**必须上板（`basessd-verify-board(上板)`）。
- **不主动 commit / push**（R3）；未上板标「未上板」（R1）。

- [ ] 取舍 / 代价写清
