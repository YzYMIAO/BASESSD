# 架构与分层决策

本 skill 只做**决策流程**。分层图、层间契约、接口清单在 `docs/`，不在这里复制（H6）。

## 0. 先读

- 分层：`docs/architecture.md`、`docs/design/fc_nand_design.md` §6.2
  （HIL / FTL / FCC / DRAM + 队列·门铃·完成；§6.2.3 是「新接口比硬件寄存器表」的判据）。
- 主流对照：`docs/design/storage_controller_design.md`、
  `docs/reference/README.md` A1 / A4（Cosmos+ / SPDK FTL 的模块分布）。
- 文件 / 头布局：`docs/guides/coding_rules.md` H51。

## 1. 分层决策

1. **定层**：HIL / FTL / FCC / DRAM；数据面 / 控制面 / 可靠性面。
   答不出就停下补理解。
2. **找出处**：§6.2 / SPDK FTL / `docs/reference/`。说不出出处标「本仓自拟」。
3. **新接口**：比硬件 FCC 寄存器表；无对应项就上移或剔除。
4. **场景轴**：DRAM 型 vs DRAM-less，说清对齐哪支。
5. **过取舍清单**：`storage_controller_design.md` §十一。
6. **偏离留痕**：代码注释写「偏离 Hxx，因为…」（P5）。

## 2. 文件 / 模块布局

用于文件臃肿、职责过多、头文件混乱、条件编译散落、跨模块搬代码；
**不是重新定层**，层边界不变时用它。

### 2.1 盘点

- 模块 / 文件 / 函数 / 类型 / 全局 / 日志 / 静态缓冲 / 条件编译 / 调用边。
- 对照公开实现（`docs/reference/README.md` A1 / A4）：核心是否薄、机制是否按状态拆。
- 列出违反 H51 的定义/原型位置和「主入口散在中部」的函数。

### 2.2 状态归属

- 先定 **状态 → 模块 → `.c` → `.h`**；谁写、谁读、谁初始化。
- `core` 只做组合根 / 生命周期 / 泵；机制模块按状态 + 不变量拆。
- 不按行数拆；优先并入已有模块；避免新 god module。
- 公共 API 与内部接口分开；不新增纯转发（public API 包装例外）。

### 2.3 目标布局

- 每个 `.c` / `.h` 按 H51 段序；模块头声明本模块接口，umbrella 只 `#include`。
- 类型/宏/普通文件级变量在第一个函数/原型之前；短函数/查询在前，实现/主入口在后。
- **注册表例外**：函数指针表 / 命令表 / 任务表 / 设备描述表放实现之后、主入口之前
  （或文件最末作数据附录）；不为表补整批 handler 原型，只在被更早函数引用时留一条表声明。
- 头文件只放声明（H12）；`static inline` 只放 H42 快路径；不循环 include。
- 需要跨模块调用时先加模块接口，不 `extern` 裸可变全局。

### 2.4 条件编译矩阵

- 列出 feature × guard × file × 生产行为。
- 测试 / 统计 / 调试 / 产品诊断分开；生产构建无测试符号。
- 定义放对应顶部段；不把 `#if` 汤留在 core。

### 2.5 链接 / 内存

- 拆文件会改对象名：检查 linker `KEEP`（hot / ITCM、`.bss` / DTCM）。
- NOLOAD 静态随模块搬时，同步 `KEEP` 与 init 函数。
- 记录拆前 map / size / ITCM；每批对比；纯 header 重排用 `.bin`/map 证明布局未变。

### 2.6 分批与验证

1. 先低风险：diag / stats / test → 再热路径。
2. move-only 分阶段；每批 build/test；不在搬移中改行为。
3. `make all` / `make release` / `make tests UT=...`；`types-check`；map/size/ITCM。
4. 按 R2：建链语义 / 位图 / 地址变化必须上板；R1 标「未上板」。

## 3. 稳定约束

- 同一语义只允许一套坐标（C9）；跨层转换只允许在单一漏斗发生。
- 文件 / 头 / 条件编译布局按 H51；模块拆解先出「状态 → 模块 → 文件 → 头」表，再谈搬代码。
- SoC 相关代码不进入 Controller / FTL / NAND **算法**模块；核心模块不直接 MMIO/HAL。
- 内存预算以链接脚本为准；提高 CH/CE/LUN 维度前先重新规划（分区表快照可能过时）。
- 「造请求者拥有 buffer 池」这类层间下界以头注释/设计文档为准，不在本 skill 复制。


落不到文件或文档章节 = 还只是印象。

## 常见失败

- 归不到「哪条主线的哪一层」就动手。
- 拿 Linux / 通用 OS 当判据。
- 新接口没有寄存器表对应项。
- 不说 DRAM 型 vs DRAM-less。
- 把「文件布局」当分层决策，或只拆 `.c` 不拆 `.h`。
- 按行数拆 / 造新 god module；umbrella 仍堆全部原型。
- 搬 hot 函数 / NOLOAD 静态不改 `KEEP` / init，ITCM/DTCM 静默变。
- 用 `git diff --stat` 代替 map/size/ITCM 证据。
