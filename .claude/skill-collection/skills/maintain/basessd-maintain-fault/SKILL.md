# 故障取证

⚠ **第一步不是改代码，是质疑证据**（P6 / §3.3）。
本仓最贵的一类故障是**没有任何报错**的故障 —— 先确认「你看到的证据成立吗」。

## 0. 先给假设

列 **3 个最可能假设** + 每个的**判据**（日志 / 计数 / 寄存器 / 负例）：

```text
假设 A：…；判据：<日志行 / 计数字段 / 寄存器>
假设 B：…；判据：…
假设 C：…；判据：…
```

一次只验证一个；证伪后更新假设。**证据无法区分假设时，先补观测，不改代码。**

## 1. 分诊

| 现象 | 去处 |
|---|---|
| 异常 / HardFault | `docs/design/common/fault_capture.md`（先读「已知限制」） |
| 断言失败 | `docs/design/common/assertion_guidelines.md` 判据 9 / 10 |
| 静默失效 / 判据无区分力 | 失败形态查 `docs/design/known_open_items.md` 与 `fault_capture.md` |
| 容量 / 统计悄悄变小（漏账） | 先怀疑不变量被多个模块手工维护（C3 / §3.1） |
| 结果不对但没崩 | 先查坐标（C9） |

## 2. 稳定判据

- 断言必须能失败（C7）；跑通 / 零告警 / 断言全绿 ≠ 功能生效（C8）。
- 位图是 **flat 绝对编号**：plane 1 的 CW0 是 `bit 4`；`1U << cw` 是 plane 盲。
  编译期完全无声，必须上板（R2）。
- 静默失效、漏账、坐标错位的**具体形态按台账条目查**，不在本 skill 复制符号
  （符号会随重构失效）。

## 3. 停手条件

- 证据无法区分假设 → **先补观测**，不改代码。
- 需要板端注入但用户未授权 → 停下报告，不自行上板。
- 无法给出**可复现负例**（C7）→ 标「待定位」，不宣称修复。
- 用户明确说「不再追」或「挂起」→ 登记台账，停止深挖。

## 产物格式

- 诊断单：现象 / 3 个假设 / 判据 / 证据 / 结论 / 负例。

## 常见失败

- 先改代码再找证据。
- 证据不能区分假设。
- 只验一条路径。
- 结论没有可复现负例。

## 完成

- 定位结论必须给出**可复现的负例**（C7），否则等于没定位。
- 报告如实标注验证状态（R1）；未上板就说未上板；**不主动 commit / push**（R3）。

- [ ] 3 个假设有判据
- [ ] 结论有可复现负例
- [ ] 停手条件已确认
