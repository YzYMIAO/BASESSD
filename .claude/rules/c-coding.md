# C 编码规则（常驻于代码路径）

本文件放**一句话规则**，触碰 `src/` / `include/` / `tests/` 文件时自动加载。
细则、理由、反例见 `docs/guides/coding_rules.md`；通用 15 章条款见
`docs/guides/coding_rules_generic.md`。

## 资源、错误与断言

**H1 资源申请与释放必须配对。** 三池（命令 / 描述符 / 缓冲）、op release 归属（`SYNC_WAIT` 不 release，其余自己 release）、buffer `buf_own`。漏配对 ⇒ 池泄漏 → 全系统 `FTL_AGAIN`，且不报错。

**H2 参数合法性检查只在模块入口做一次，内部默认合法。** 边界 = host 入口返回码 + FTL↔FC / 子模块入口 `ASSERT`；内部逐函数复检是纯开销。详见 `docs/design/common/assertion_guidelines.md §九`。

**H14 关键处用 `ASSERT`；「内部免检」正是靠它零开销。** 位置 = 不变量 / 前置条件 / 不该发生的状态；release（`NDEBUG`）展开为 `((void)0)`；**有副作用的调用不能进 `ASSERT`**；后果是静默介质破坏时，除 `ASSERT` 外必须再补 release 运行期拒绝。

**H30 库函数 / HAL 返回值必须处理。** 允许显式 `(void)` 丢弃，不允许静默忽略；失败后果是静默介质破坏时走 H14 的 release 拒绝。

## 控制流与周边

**H5 废弃代码及时清除。** 注释掉的代码、死函数、过时守卫，收口时删干净。

**H6 改代码时同步维护周边注释。** 注释与代码不一致 = 缺陷。

**H7 `switch` 必须有 `default`。** 见 `CLAUDE.md §四` 例外。

**H8 禁止 `goto`，唯一例外是统一错误出口。** 见 `CLAUDE.md §四`。

## 类型、位运算与整数

**H3 整数运算必须考虑溢出，先判后算。** `if (a > SIZE_MAX - b) 报错; else c = a + b;`；无符号回绕同为缺陷，有符号溢出是 UB。

**H4 禁止魔鬼数字。** 尺寸 / 容量常量用宏，**必须注明来源与推导**；把「估值」写成「上界」是已发生缺陷。

**H9 固定宽度整数统一用项目别名 `BYTE / WORD / DWORD / QWORD`。** 不写 `uint8_t`；不设二级地址别名（LBA / PAA / PBA 直接 `DWORD`）；第三方 / CMSIS / HAL 保持原生 `uint*_t`；用别名必须 `#include "ssd_types.h"`。

**H15 位运算与位判断必须走公共宏，不在业务代码手写位表达式。** 宏名必须区分「任一位置位」与「全部位置位」；通用位运算进 `include/common/`；新增前先找 `NAND_FIELD_MASK`。

**H22 隐式窄化转换必须显式化。** 宽赋窄必须写显式转换或先 `& MASK`；H48 是其落地细则。

**H23 移位量必须小于类型位宽；位运算只用于无符号类型。** 掩码带 `U`；移位前先与位宽比一次。

**H31 数组下标与指针必须做边界判断。** 位图是 **flat 绝对编号**，下标越界不会崩溃，只会改错 plane 的位。

## 嵌入式运行时

**H16 `volatile` 只用于三处，且它不是同步手段。** 硬件寄存器 / ISR 与主循环共享变量 / DMA 可见缓冲区；顺序敏感处配 `__DMB()`；多字节共享仍需临界区。

**H17 DMA 缓冲区必须做缓存维护，地址与长度按 32 字节对齐。** CPU→设备 Clean；设备→CPU Invalidate；漏 Invalidate = 拿错数据继续跑。

**H18 临界区必须用可嵌套的 PRIMASK 保存 / 恢复，不用裸 `__disable_irq()` / `__enable_irq()`。**

**H19 递归必须有深度上界——本仓不禁止递归，禁止无界递归。** 深度由数据结构保证（树高 / log n），不是输入决定。

**H20 看门狗：长操作必须喂狗，且喂狗点不能被慢路径饿死。** IWDG 当前所有构建档关闭，启用与否是待上板决策；不在 ISR 喂狗。

**H21 ISR 必须短、不阻塞、可重入；重活延后到主循环。** 禁止 `LOG*` / `ASSERT` / 动态分配 / 等待轮询 / FTL·NAND 事务；ISR 置标志，主循环执行。

## 结构与模块

**H10 全局可变状态必须单点修改。** 嵌入式静态分配是常态，适用的是**唯一闸门**；allocator 的 free / op / spare / closed_sb_list 四个账本（本仓简称「四本账」）教训即此条。

**H11 函数嵌套 ≤4 层。** 不设函数行数上限；行数不是拆分函数的判据，可读主干优先。

**H12 头文件职责单一：只放声明不放变量定义，且必须自包含。** 有 `#ifndef` 守卫，禁止 `#pragma once`，禁止循环依赖。

**H13 模块化：一个模块只做一件事；模块间只通过接口通信，不碰对方内部数据。** 耦合过重的信号 = 改 A 模块被迫去改 B 的内部。accessor 过三问：值域检查 / 隐藏数组 / 账本单点；皆否直接写 `s->field`。

## 命名、宏、变量、表达式

**H24 命名规范。** `snake_case` 变量 / 函数、宏全大写、全局 `g_` 前缀、`static` 文件级 `s_` 前缀；禁止拼音、无意义单字符（循环 `i/j/k` 除外）。

**H25 宏的写法。** 表达式宏每个参数与整体加括号；多条语句必须 `do { ... } while (0)`；宏参数不得有副作用。

**H26 变量必须先初始化后使用。** `.noinit` 不清零，容易把复位残留误当初值。

**H27 通讯 / 持久化结构体必须显式约定字节序。** 跨边界每个多字节字段注释写清；主机序↔小端只允许在单一漏斗发生。

**H28 表达式不依赖求值顺序、禁止嵌套赋值、自增自减独立成句。**

**H29 严禁使用未经验证的输入数据。** 来源是介质 / 上位机 / CLI 一律按不可信处理，边界必须校验；`journal` 回放刻意不转断言。

## 状态、返回、守卫、声明、注释

**H32 状态字段用互斥枚举，不用软件位图。** 一位两义即缺陷；正交维度拆独立字段；转移收敛到唯一 setter；已有同值域枚举不新建第二套。

**H33 布尔与多态返回码。** 项目布尔一律 `BOOL`（1 字节 `_Bool`）；不新增 `xxx_bool_t`；多态返回码拆具名枚举；同值反义不得共用通用枚举；值域不是真值域的不改 `BOOL`。

**H34 入口守卫的收口判据。** 调用者自己持有的指针 / 索引 → `ASSERT`；host 输入 / 介质读回 / 池空 / 表满 → 保留返回码。热路径不是保留 `if` 的理由；被 `ASSERT` 守的形参 release 变 unused 时先判废形参，不用 `(void)param` 糊。

**H35 变量声明就近使用处（C99）。** 判据 = 首次使用的那一行声明，不提到函数 / 块开头。

**H36 命名即语义：字段名不得撒谎。** 字段名与语义相反 ⇒ 改名，不靠谓词 / 注释兜；为兜坏名字而存在的谓词，改名后应删。

**H37 注释只描述当前设计，不承载变更史。** 删版本号 / 日期 / 「原先…」/ 历史复盘；变更史归 git / `docs/archive`；删除叙事时不得丢信息；已删除函数 / 字段不留墓碑。

**H38 返回值与数据分离。** 状态用 `ftl_status_t` / `bool`，数据只走出参；返回值恒为常量或唯一调用点恒丢弃 ⇒ 改 `void`；`FTL_ERROR` = 永久失败，`FTL_AGAIN` = 瞬态资源。

**H39 维度常量不得写死下标。** 由 `*_NUM` 定义的维度，初始化 / 复制 / 比较 / 日志一律 `for` 循环，不写 `[0]` / `[1]` 字面量。

**H40 枚举 / 值域参数入口断言，`*_NUM` 宏用于边界。** 零消费者 = 死宏，要么用于断言，要么删。

## 头文件、内联、强转、实参、状态码、初始化

**H41 项目头文件一律纯文件名（bare header name），禁止目录前缀与相对路径。** 系统头 `<>`，项目头 `""`；新增头文件目录必须同步 `MODULE_INCS`；同名风险先 `find ... -name` 查重。

**H42 头文件 `static inline`：纯函数 + 单字段 fast path；慢路径 / 回调 / 日志 / 顺序不变量放 `.c`。** 宏只用于编译期常量；`static inline` 不是内联保证。

**H43 显式强转只用于有信息损失的转换。** 保留窄化 / 符号 / 宽度 / printf ABI / reinterpret / `(void)`；删除同型、常量固有类型、装饰性强转；`DWORD` ≡ `unsigned long`，配 `%lu` 的 `(unsigned long)` 必须删。

**H44 强转先查被调方：调用点反复出现的窄化强转，多半是返回值类型设计过宽。** 有自然值域用最窄标准类型，窄化收敛到生产者内部一次；无自然值域保持宽类型。

**H45 函数实参不得承载「第二段逻辑」；先落语义化局部变量，再调用。** 结构体字面量、指针差、嵌套调用、下标 / 解引用、三元 / 逻辑式都先落局部。

**H46 返回值状态码一律非负：0 = 成功 / 默认，其余为具名非负码；禁止 `-1/-2`。** 按具名常量比较，禁止 `status < 0`；已有 0 语义的步进枚举不重排。

**H47 局部结构体一律「先声明、后逐字段赋值」；初始化列表只用于数组表与文件级 / 全局结构体。** 局部 `T x = {0}` 改 `memset`。

**H48 优先用「声明宽度 / 有界值 / 赋值转换」消除强转，不要在每个使用点重复 cast。** 消除顺序：改声明 → 有界值隐式截断 → 删冗余外层 cast；移位 / 乘法前的加宽与 printf ABI 必须保留。

**H49 优化 / 重构一个模块时，顺序固定：命名 → 布局 → 调用链 → 封装 / 断言。** 不得先堆小函数再改名；封装必须换来复用 / 守卫 / 模块边界之一。

**H50 复合类型 / ID / 函数指针 / 数组的类型别名统一定义、统一后缀、统一缩写。** 定义处带 `typedef` + tag；alias 后缀 `_s/_e/_u`；派生类型 `_id_t/_fn_t/_arr_t/_t`；缩写查表；`make types-check`。

**H51 `.c` / `.h` 文件内布局：文件级定义在第一个函数 / 原型之前；短函数 / 查询在前，实现 / 主入口在后。**
`.c`：文件头 → include → 宏 → 类型 → 文件级变量（`g_*` / `s_*` / `static const`）→ static 前向声明 → 短函数（≤4 NBNC 分派 / 查询 / 谓词 / 纯包装）→ 实现 → **注册 / 分发表** → 主函数 / 几大入口。
`.h`：guard → 文件头 → include → 宏 → 类型 → extern 声明 → `static inline` 短 fast path → 原型（查询 / 谓词 / getter 在前，`*_init` / `*_service` / `*_handle` / `*_step` / `*_submit` / `*_begin` / `*_run` 在后）→ `#endif`。
定义不得夹在函数 / 原型之间；`.h` 只放声明（H12），`static inline` 只放 H42 快路径；主入口即使短也放最后；函数内局部变量仍按 H35 就近。
**注册表例外：** 函数指针表 / 命令表 / 任务表 / 设备描述表若以本文件函数为初始化项，放在**被引用函数之后、主入口组之前**；也可放文件最末作为数据附录（此时 `main` 仍是最后一个函数）。不为表前置声明整批 handler 原型；表被更早函数引用时，只在 static 声明区保留一条表自身声明（如 `static const bg_task_s s_bg_policy_tasks[BG_POLICY_TASK_COUNT];`）。普通 `static const` 常量表仍放文件级变量区。

## 注释风格（S）

**S1 对齐周围代码。** 注释密度、命名、惯用法照抄邻近代码，不引入新风格。

**S2 注释解释 why，不重复 what。**

**S3 注释放代码上方或右方，不放下方。**

**S4 中文注释。** 本项目文档与注释均为中文。

**S5 注释分两层：函数契约用 `/** */`，实现细节用 `//`。** 契约块含 `@brief` / `@param` / `@return` / `@note`；`.h` 声明与 `.c` 定义各自带完整契约且一致；`@param` / `@return` 只允许出现在 `/** */` 内；契约块标题等于紧随函数名。

**S6 注释机械自查。** 函数前不得再有普通 `/* */` 块；`@param` / `@return` 不得出现在非 `/** */` 块内；变更史 grep 应为 0（例外：许可证版本、介质布局版本常量）。
