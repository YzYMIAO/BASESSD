# 故障取证

⚠ **第一步不是改代码，是质疑证据**（CLAUDE.md P6 / §3.3）。
本仓最贵的一类故障是**没有任何报错**的故障 —— 先确认「你看到的证据成立吗」。

---

## 0. 先分诊：这是哪一类？

| 现象 | 类别 | 去处 |
|---|---|---|
| 停机、串口打出 HardFault dump | **异常** | §1 |
| 打出 `assertion_fail` | **断言** | §2 |
| 跑通、零告警、断言全绿，但**功能没生效** | **静默失效** | §3 |
| 断言/测试**恒真**、怎么改都通过 | **判据无区分力** | §3.2 |
| 只有容量/统计数字悄悄变小 | **漏账** | §4 |
| 结果不对但没崩 | **先查坐标** | §5 |

---

## 1. 异常（HardFault / MemManage / BusFault / UsageFault）

- 串口 dump 机制见 `docs/design/fault_capture.md`；记录落在 `.noinit` 段。
- CLI `crash` 看记录、`crash clear` 清记录。
- 复位原因：`POR PIN BOR SFT (rsr=0x...)`。

**先读 §8「已知限制」再下结论**，否则会误判：
- **栈溢出型故障可能根本打不出来**（压帧再次失败 → Lockup），这类只能靠 SWD 看 `CFSR`。
- **`usart_init()` 之前的故障**只写记录不打印。
- **`.noinit` 只跨软复位**：硬复位/掉电后记录丢失。
- **`IMPRECISERR`**（写缓冲导致的不精确总线错误）**栈里的 PC 可能已经跑远** ——
  此时 PC 不一定是出错指令，别拿它直接定位。
- **dump 期间中断是关的**，期间有别的故障源会直接锁死（这是「停机保留现场」的代价）。

⚠ 用 **SWD** 读 `CFSR`/`HFSR` 时注意：**读可缓存内存会绕过 D-Cache 拿到陈旧值**。

---

## 2. 断言失败

- `assertion_fail(#expression, file, line)` 会打表达式原文 + 文件 + 行号。
- **release 档没有断言**（`NDEBUG` 下 `ASSERT` 展开为 `((void)0)`）——
  所以在 release 上看到的现象是**别的**（静默损坏 / HardFault），不要按 debug 的思路找。
- 判据体系见 `docs/design/assertion_guidelines.md`（**判据 9**：后果是静默介质破坏的，
  除 debug ASSERT 外必须补一道 release 运行期拒绝；**判据 10**：被 ASSERT 守的变量在
  `NDEBUG` 下变 unused ⇒ release 档的编译告警是「这条断言在 release 下没有等价守卫」的唯一提示）。

---

## 3. 静默失效 / 判据无区分力（CLAUDE.md §3.2）

**症状**：跑通、零告警、断言全绿，但功能从未生效。

本仓已发生的形态（照着找同类）：
- **CRC 恒通过**：`FC_CRC_BASE` 写成 ADC3 的地址 ⇒ `g_crc_ready = 0`（设计上「失败静默继续」）
  ⇒ `fc_crc_compute()` 恒返 0 ⇒ 比 `0 == 0`。
- **状态字节被丢弃**：`fc_complete_from_nand` 从不读 `nand_status` ⇒ 7Ah 状态字节在边界消失。
- **参数白设**：`plane_paa[]` 未填 ⇒ 恒寻址 block 0。
- **恒真断言**：`stored == fc_crc_compute(plain)` 同函数算同段数据。
- **测试碰巧通过**：`expected_byte` 用 `(block << 8 | page << 4 | plane)` 后 `(uint8_t)` 截断
  ⇒ block 参数完全不影响结果，而 102 与 100 **碰巧截断相同**。
- **只验一条**：某步校验只验 page 0 ⇒ page 1–62 的损坏全漏。

**判据（C7 / C8）**：
- 断言要能失败 —— 必须构造**一个必然让它失败的输入**（负例）。
- 「生效过」必须有证据 —— **跑通 ≠ 生效**。

## 4. 漏账（CLAUDE.md §3.1）

**症状**：不报错、不崩溃，只表现为**容量无声流失**，最终写永久 `FTL_AGAIN`。

**归因优先怀疑**：同一不变量由**多个模块各自手工维护**（C3），不是命名或结构问题。
实例：allocator 的「四本账」、`closed_sb_list` 满时静默丢条目。
**对策**：收敛成唯一闸门 + 账本访问器。

---

## 5. 结果不对但没崩 —— 先查坐标（C9）

**同一语义只允许一套坐标**。出现「第二套坐标」即为缺陷：
`cw_count[]` / `cws[][]` / `slot_to_plane_cw` 之类。
跨边界转换（PBA↔PAA）只允许在**单一漏斗**发生，现场手写位操作 = 缺陷。

⚠ 位图相关的**头号坑**：**位图是 flat 绝对编号** ——
plane 1 的 CW0 是 `bit 4` 不是 `bit 0`；`1U << cw` 是 **plane 盲**位图。
这类错值**编译期完全无声**，必须上板（R2）。

---

## 6. 收尾

- 定位结论必须给出**可复现的负例**（C7），否则等于没定位。
- 报告如实标注验证状态（R1）；未上板就说未上板。
- **不主动 commit / push**（R3）。
