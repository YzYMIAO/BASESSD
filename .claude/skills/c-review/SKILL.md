## 0. 审查顺序（六遍）

按「先结构后细节」走，**不要一上来就看表达式**。

### 第 1 遍 · 结构与模块（H10 / H11 / H12 / H13）

- [ ] 一个函数只做一件事？新增函数 ≤50 行（NBNC）、嵌套 ≤4 层？
- [ ] 头文件只放声明、不放变量定义、自包含、有 `#ifndef` 守卫、无循环依赖？（H12）
- [ ] include 是否**纯文件名**（无目录前缀 / `../` / 绝对路径）？（H41；
      `grep -rnE '^\s*#\s*include\s*"[^"]*/' src include tests` 应为 0）
- [ ] 头文件 `static inline` 是否只放纯函数？写闸门 / 非平凡逻辑是否在 `.c`？（H42）
- [ ] accessor 是否过「三问」（值域检查 / 数组隐藏 / 账本单点）？全否应直接访问字段。（H13）
- [ ] **模块间有没有直接摸对方内部数据**？判据：**改 A 时被迫去改 B 的内部** = 耦合过重，
      该给 B 加接口而不是改 B。（H13）
- [ ] 全局可变状态是否**单点修改**？（H10）
- [ ] 同一不变量是否被**多个模块手工维护**？—— 这是本仓头号可读性根因（C3 / §3.1）。

### 第 2 遍 · 资源与错误路径（H1 / H14 / H30 / C5）

- [ ] 申请/释放**配对**？（三池：命令 / 描述符 / 缓冲；op release 归属；buffer `buf_own`）
      **漏配对的症状是池泄漏 → 全系统 `FTL_AGAIN`，且不报错。**（H1）
- [ ] 库函数 / HAL 返回值处理了吗？允许 `(void)` 显式丢弃，**不允许静默忽略**。（H30）
- [ ] 参数校验**只在模块入口做一次**？（H2 —— 内部逐层复检是纯开销）
- [ ] 该用 `ASSERT` 的地方用了吗？**有副作用的调用进 `ASSERT` 了吗**？（H14 陷阱）
- [ ] 后果是**静默介质破坏**的错误，release 下有没有运行期拒绝？（C5 / 判据 9）

### 第 3 遍 · 类型与运算（H3 / H4 / H9 / H22 / H23 / H43 / H44）

- [ ] **隐式窄化转换**有没有显式化？「值域放得下但类型放不下」必须有 `(uint8_t)` 或先 `& MASK`。（H22）
- [ ] 每个**显式强转**是否必要？同类型 / 常量 / 装饰性强转删掉；窄化、符号/宽度、printf ABI、reinterpret、`(void)` 保留。（H43）
- [ ] 强转是否在**为过宽的 API 返回值**买单？同一返回值在多个调用点反复窄化 ⇒ 改生产者返回类型到自然宽度，删除调用点强转。（H44）
- [ ] 移位量 < 位宽？位运算只用于**无符号**？掩码带 `U` 后缀？（H23）
- [ ] 溢出检查是「**先判后算**」还是事后看结果？（H3 —— 有符号溢出是 UB，事后检测会被优化掉）
- [ ] 魔鬼数字？（H4 —— 且**必须注明来源与推导**，把「估值」写成「上界」是本仓已发生的缺陷）
- [ ] 精确宽度整数（`uint32_t` 等）？新代码**不要**再用 `DWORD`/`WORD`/`BYTE`。（H9）

### 第 4 遍 · 嵌入式运行时（H16~H21）—— **最容易漏的一遍**

- [ ] `volatile` 用在硬件寄存器 / ISR 共享 / DMA 可见缓冲区了吗？**顺序敏感处配 `__DMB()` 了吗**？（H16）
- [ ] DMA 缓冲区做了缓存维护吗（Clean / Invalidate）？**地址与长度 32 字节对齐**了吗？（H17）
- [ ] 临界区用**可嵌套的 PRIMASK 保存/恢复**了吗？**不要**用裸 `__disable_irq()`/`__enable_irq()`。（H18）
- [ ] 递归深度是**数据结构保证的**（树高 / log n）还是**输入决定的**？后者会打爆栈。（H19）
- [ ] 长操作覆盖喂狗点了吗？喂狗点是否被慢路径饿死？（H20）
- [ ] ISR 够短吗？有没有阻塞调用 / 不可重入调用 / `LOG*`？（H21）

### 第 5 遍 · 复用与坐标（R9 / C2 / C9）

- [ ] 新增的**位操作 / 地址转换 / 结构体构造 / 相似分支**，**有没有手工等价物已经存在**？
      判据是「有没有手工等价物」，**不是**「有没有被调用」。（C2）
- [ ] 出现**第二套坐标**了吗（`cw_count[]` / `cws[][]` / `slot_to_plane_cw` 之类）？（C9）
- [ ] 位图是不是 **flat 绝对编号**？plane 1 的 CW0 是 `bit 4` 不是 `bit 0`；
      `1U << cw` 是 **plane 盲**位图。（§3.2）
- [ ] 位判断是不是手写的 `(x & MASK) != 0U`？该走公共宏（H15）。
      ⚠ 分清**任一位置位**（`!= 0`）与**全部位置位**（`== m`）—— 宏名必须写出来。

### 第 6 遍 · 注释与可读性（H6 / H26 / S1~S4）

- [ ] 注释与代码一致吗？（H6 —— 不一致 = 缺陷）
- [ ] 变量都初始化了吗？（H26 —— `.noinit` 段不清零，容易把复位残留误当初值）
- [ ] 跨边界结构体（介质 / 上位机）的**字节序写明了吗**？（H27）
- [ ] 注释解释 why 而非 what？在代码上方或右方？中文？（S2 / S3 / S4）
- [ ] 有没有对齐周围代码的风格？（S1）
- [ ] 废弃代码、注释掉的代码清干净了吗？（H5）

## 1. 本仓特有的「别修好」清单（CLAUDE.md §四）

这些**看起来像 bug，其实是有意设计** —— 审查时**不要**报为缺陷，**动之前先问用户**：

- `src/ftl/read_recovery.c` 的 `RR_FEATURE_READ_RETRY = 0x89` 在本器件是**保留地址**、自始空转 —— 用户明确不处理。
- `src/fc/fc.c` 的 4 处 `goto stripe_error` 是**合规**的统一错误出口。
- `switch` 里非法 `phase` 的 `default` 带 release/复位副作用，是**有意设计**。
- `fc_bch_decode` 的 ASSERT 必须在**函数体首条语句**。
- `fc_command_release` 的幂等早退、`pop_n(ids == NULL)`、`fc_bch_encode(ecc == NULL)` 是有意语义，不转 ASSERT。
- `fault_port.c` 的 FPU 帧极性判断是对的。
- `FTL_BLOCK_STATE_FREE` 会说谎；`[FTL] dangling` 是常驻守卫勿删。
- `src/ftl/journal.c` 整体不转断言（校验的是**从 NAND 读回的不受信数据**，H29）。
- 历史 changelog 正文不改写。

## 2. 输出格式

- 按**严重度排序**，每条给 `文件:行号`。
- 每条写清：**哪条规则**（R/C/H/P/S 编号或华为条目号）→ **具体缺陷** → **失败场景**（什么输入导致什么后果）。
- ⚠ 说不出「失败场景」的，说明还只是**风格偏好**，归 §七 建议 S，不要当缺陷报。
- ⚠ 报缺陷前先按 **C7** 自问：**这条判断能失败吗**？（恒真的判据比没有判据更糟）
- ⚠ **发现即登记（R11）**：每条缺陷 / 判定结论都要同步写进 `docs/design/known_risks.md`
  对应模块分节（含「看起来像缺陷、其实是有意设计」的结论）；只在本回复里列出 = **未完成**。
  说不出失败场景的归 §七 S，不进表。
- **不主动改代码**（R7 讨论期）；**不主动 commit / push**（R3）。
